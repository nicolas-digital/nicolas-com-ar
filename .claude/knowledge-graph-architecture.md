## I. FUNDAMENTO DEL KNOWLEDGE GRAPH

### ¿Por qué Knowledge Graph y no solo "Topic Clusters"?

| Enfoque | Resultado | SEO | LLM Citable | Diferenciador |
|---------|-----------|-----|-------------|---------------|
| **Blog tradicional** | Posts aislados | Bajo | No | Generic |
| **Topic Clusters** (Pillar + satellites) | Agrupación básica | Medio | Maybe | Standard |
| **Knowledge Graph** (Nodes + edges) | Sistema interconectado | Alto | Sí | **ÚNICO** |

**Knowledge Graph = MIT/McKinsey model en español**

Google, Claude, ChatGPT, Perplexity pueden navegar tu grafo.

## IX. IMPLEMENTACIÓN EN CÓDIGO

### Estructura de datos:

```typescript
// lib/knowledge-graph.ts

type NodeType = "pillar" | "subnodo" | "article" | "transversal";
type Connection = "requires" | "enables" | "impacts" | "supports";

interface KnowledgeNode {
  id: string;
  title: string;
  type: NodeType;
  pillar: string; // "retail-strategy" | "commerce-platforms" | etc
  description: string;
  keywords: string[];
  connections: {
    nodeId: string;
    type: Connection;
    anchorText: string;
  }[];
  transversals: string[]; // "data", "cx", "economics"
}

// Example:
const aiMerchandisingNode: KnowledgeNode = {
  id: "ai-merchandising",
  title: "AI Merchandising Strategy",
  type: "subnodo",
  pillar: "ai-retail",
  description: "...",
  keywords: ["AI merchandising", "AI pricing", "demand forecasting"],
  connections: [
    { nodeId: "retail-strategy", type: "impacts", anchorText: "drives growth" },
    { nodeId: "commerce-platforms", type: "requires", anchorText: "composable architecture" },
    { nodeId: "digital-operations", type: "enables", anchorText: "operational integration" },
    { nodeId: "retail-media", type: "supports", anchorText: "discovery monetization" }
  ],
  transversals: ["data", "cx", "economics"]
};
```

## XII. CRÍTICA Y RIESGOS

### Riesgo 1: Complejidad
**Riesgo:** ¿Y si el grafo es demasiado complejo?

**Mitigación:**
- Visualizar grafo en site (interactive graph?)
- Cada artículo: "Contexto del artículo" → muestra su lugar en grafo
- Series temáticas que guíen navegación

### Riesgo 2: Fricción de implementación
**Riesgo:** ¿Y si es tedioso mantener conexiones?

**Mitigación:**
- Automatizar sugerencias de conexiones (mismo pilar, mismo transversal)
- Checklist en cada artículo nuevo: "¿Conecta con qué nodos?"
- Template reutilizable

### Riesgo 3: Sobre-linking
**Riesgo:** ¿Y si pongo links en todo y pierdo focus?

**Mitigación:**
- Max 3-5 links por artículo (quality > quantity)
- Solo links relevantes semánticamente
- "Related insights" al final (3-5 artículos)
